## Problem Statement

The user's words: "On the puls.html site I want to finally completely clean up and
improve the Zusammenfassung der aktuellsten Sitzung section. The Redeanteile nach
Fraktion is repeated below in a much better way (the numbers actually show how much
percentage each was, so the user doesn't have to guess). Also the Meiste Aufmerksamkeit
section feels weird since it takes up all of the bottom right, but the Redeanteile nach
Fraktion only part of the bottom left. Maybe before trying to fix the individual parts,
we should think about what the puls.html page should actually be."

What the page does today (`scripts/build_dip_pulse_site.py:render_front_page`, ~line 2070),
verified on the built site for KW 24/2026:

- The hero is one sitting (`entries[0]`, BT-PlPr 21/84, a Friday with 99 speeches) while
  the Wochenvergleich below is the ISO sitting week (409 speeches across 21/82–84). Two
  clocks on one page; the green "Themenbewegung" card glues them with two sentences that
  both appear elsewhere.
- "Meiste Aufmerksamkeit" never names a topic. It renders the XML `heading`, which is
  procedural boilerplate first ("Erste Beratung des von der Bundesregierung
  eingebrachten Entwurfs eines…"). The DIP Vorgang title on the same item
  (`api.positions[].titel`) is topic first ("Gesetz zur Stabilisierung der Beitragssätze
  in der gesetzlichen Krankenversicherung"). Measured over 286 cached dossiers: 2112 of
  2866 agenda items (74%) carry a Vorgang title; 695 carry several (a/b/c grouped items).
- The Fraktion split is rendered twice by two components: `render_party_stack` + count
  badges in the hero (no percentages, "+2 weitere"), `render_share_shift` in the
  Wochenvergleich (bars, %, pp delta). The worse one sits in the hero.
- The hero's paragraph describes the page, not the sitting, and repeats the header subtitle.

## What Makes This Cool

Opening puls.html on a sitting-week morning and reading, in five seconds, *what* the
Bundestag was about this week: five debates named by their subject, who carried each
one, which ones came back from an earlier week, every row one click from the protocol.
The June design doc's line: "Here is what the Bundestag spent attention on, with
receipts." Today the page answers "how much"; after this it answers "what".

## Constraints

- Static HTML from cached dossiers; no framework, no chart library; the only scripts are
  the inline blocks the site already emits. Dark mode and puls.html's 980/700/460px
  breakpoints exist and must keep working; rules that hide content must be `screen`-typed
  (see learnings).
- Every number one click from its source; no claim of political importance from a count.
- Bausteine: votes and summaries are optional; the page must be complete with both off.
- The hero must not be a copy of the dossier's "Aufmerksamkeitsrang" sidebar (user's
  explicit constraint).
- Solo side project: keep the moving-parts count low; logic in pure, testable helpers.

## Premises (agreed)

1. puls.html has one job: what the Bundestag spent attention on in the newest sitting
   week, with receipts. Not a dossier preview, not a stats page.
2. The unit of the whole page is the ISO sitting week (`iso_week_key`). The newest dated
   week is shown even mid-week. Whether the week is still running is decided by the
   build clock, not the data: `render_front_page(..., today=, week=)`, fed by the build
   CLI (`--today YYYY-MM-DD`, else `SOURCE_DATE_EPOCH` read as UTC, else the current
   date; `--week YYYY-WW` pins the sitting week and fails before any file is written when
   the week has no cached dossier). Running iff Monday ≤ `today` ≤ Sunday of the week:
   h1 "… bisher verhandelt hat", facts line "Stand 09.09.2026: 1 Sitzung erfasst,
   Sitzungswoche läuft". Past week within one ISO week: "Stand: 3 Sitzungen, letztes
   Protokoll 21/84 verteilt am 15.06.2026 · Auswertung vom 15.09.2026". Older: eyebrow
   "Letzte Sitzungswoche" and the line leads with the age, "Letzte Sitzungswoche vor 13
   Wochen · …" (ISO-week difference). The clock label is always "Auswertung vom", never
   "Datenstand" (a stale cache rebuilt offline can hold one sitting of a week that is over;
   the data cannot tell, so the page never claims "abgeschlossen"). A `verteildatum`-based
   rule was checked and rejected: 6 of 95 cached weeks distribute their last protocol
   before Sunday. If no entry carries a `datum` (`group_entries_by_week` drops undated
   entries, render ~1140), the empty-state shell renders with the sentence "Die
   erzeugten Sitzungen tragen kein Datum, ein Wochenradar ist nicht möglich." instead of
   "Es wurden noch keine Sitzungen erzeugt." The "Neuestes Protokoll" action always links
   the newest dated entry's dossier.
3. Ranking = share of the week's speeches per TOP, the signal the site already uses. The
   visible number is "N Reden · X %", the denominator is stated once in the section's
   method note ("Anteil an allen 409 Reden der Woche"); nothing is labelled
   "Aufmerksamkeit" as a claim.
   Evidence for keeping speech count over text volume: over all 285 complete-text dossiers
   the top 5 by count and by chars share ≥4 items in 264 sittings (93%); the #1 agrees in
   170 (60%) and the disagreements are near-ties. The hero differs from the dossier
   sidebar on every axis: week not sitting, capped to 5, Vorgang-titled, rows carry
   who/since-when instead of speech/text mini-bars.
4. A topic row is named by its DIP Vorgang title(s). Procedures are collected from
   `api.positions` in DIP order and then from each position's `mitberaten` twins (every
   twin in the cache carries id, titel, vorgangstyp, vorgangsposition; in 40 TOPs the only
   Gesetzgebung procedure is a twin), first-seen dedup by id, titles compared after
   whitespace normalisation. A grouped TOP (a/b/c) stays one row with one share; the share
   is never split per title. Lead: the first Gesetzgebung procedure, else the first
   procedure. **Gate decision (D16):** a group with no Gesetzgebung and more than one
   distinct title has no lead title; the row shows its type label first ("Antrag ·
   Beratung · 4 Anträge gemeinsam") and every title at equal weight (up to 3, then "und N
   weitere" linking the dossier TOP), so DIP ordering never promotes one Fraktion's
   framing. Gesetzgebung-led groups keep the lead title with siblings on a "mit:" line.
   Heading-order matching was checked and rejected: only 221 of 542 sibling titles occur
   verbatim in the heading. Type label counts procedures, never titles: "Antrag ·
   Beratung · 4 Anträge gemeinsam"; mixed "Gesetzgebung · 1. Beratung · mit 2 Anträgen";
   neutral fallback "mit N weiteren Vorlagen". Items without any title fall back to
   `short(heading, 120)`, then `top_id`, then "Tagesordnungspunkt N"; the chain never
   applies to an equal-weight row. No
   boilerplate stripping in v1: of 459 ranked top-5 rows in the cache, the 61 untitled
   ones are budget Einzelpläne (empty heading, `top_id` "Einzelplan 12"),
   Regierungserklärungen and "Zur Geschäftsordnung", all already subject-first. A stripper
   is a follow-up once a boilerplate-first heading actually reaches the top 5.
5. Every breakdown appears once. The week-wide Fraktion split is rendered by one
   component (`render_share_shift`, in the Wochenvergleich); the per-row "Wer sprach"
   stacks are per-TOP breakdowns, a different number. The week totals (Reden, TOPs) are
   restated once as the denominator in the header sentence and once with deltas in the
   Wochenpuls card. The four hero fact tiles go (Drucksachen and Personen were
   sitting-level facts with no consumer).
6. The "Themenbewegung / Was nach vorne rückt" card is dissolved. The votes card stays,
   renamed "Namentliche Abstimmungen" (no promise sentence), and aggregates over the week
   by distinct vote id (a vote matched to two TOPs of one sitting counts once; 29 of 246
   attachments in the cache). Baustein semantics are the
   site's existing ones: `publication_selection()` is `all_selection()`
   (`scripts/features/__init__.py:111`), so every Baustein-dependent block is always
   rendered and carries `data-feature="votes"` / `data-feature="summaries"`; the visitor's
   settings hide it client-side. The page must read correctly with either block hidden.
7. Question formats stay in the denominator but are not ranked as topics; they get one
   "Außerdem" line under the rows with count, share and dossier link. Match rule:
   `is_question_format(item)` = whitespace-normalised heading starts with one of
   "Befragung der Bundesregierung", "Fragestunde", "Regierungsbefragung" (prefix match:
   the cache has "Befragung der Bundesregierung (einleitend BMJ)" and two Anträge with
   "Befragung" mid-string that must not match). Evidence: Befragung der Bundesregierung
   would be row 1 in 74 of 95 sitting weeks (each question and answer counts as a Rede;
   116 of 409 speeches in KW 24, 7,360 over the archive). It is a format, not a subject,
   and it is identical every Wednesday.

## Cross-Model Perspective

Codex (gpt-6-astra, cold read of a structured summary, read-only against the repo):

- Coolest version: "a weekly briefing with a memory" — each row expands into the
  procedure's sourced history using recorded `vorgangsposition` values and
  `returning_vorgaenge()`'s first/latest occurrences; a plain `<details>`, no JS.
  Boundary it named: a grouped TOP is one debate with one share; giving each title the
  whole share would manufacture attention. Adopted as premise 4; the expansion is
  deferred (Approach C).
- Strongest signal it read: the user's unsolicited "the attention part should not be a
  copy of the Aufmerksamkeitsranking" — "they want an editorial product with its own
  reason to exist".
- Challenged premise 3 (count as "attention"). Its proposed test was run (above); the
  ranking stays, its labelling point is adopted.
- Weekend build: reuse `group_entries_by_week`, `week_stats`, `item_stats`,
  `returning_vorgaenge`, `render_share_shift`; add `topic_identity()`,
  `week_topic_rows()`, `render_week_topic_radar()`; identify rows by dossier + TOP index
  (indices repeat across sittings); exclude zero-speech TOPs; two reuse traps:
  `render_party_stack()` clamps every segment to ≥4% width (distorts small shares), and
  `render_session_llm_summary()` builds `#anchor` links that only resolve on the dossier
  page (extract the receipt-link construction into a helper taking a dossier href).
  History must read "first seen in this archive", not proven inception. All adopted.

## Approaches Considered

- **A: Hero swap (minimal).** Replace the lede's insides only; Wochenvergleich untouched.
  Rejected: keeps the 4% stack clamp and first-title-only naming, no summaries, votes card
  stays per sitting. Completeness 6/10.
- **B: Week radar (ideal). Chosen.** See below. Completeness 9/10.
- **C: Briefing with a memory.** B plus a `<details>` trajectory per row across the
  archive and a Neu/Fortgesetzt marker. Deferred: tallest hero, awkward at 400px, and the
  trajectory belongs to a future bill page (bills Baustein). Purely additive on B's data
  model. Completeness 10/10.

## Recommended Approach: B — Week radar

Page anatomy, top to bottom (wireframe: docs/designs/puls-wochenradar-sketch.png):

1. **Global header** unchanged.
2. **Page header = the week's identity.** Eyebrow "Sitzungswoche · Aktueller Puls";
   h1 "Was der Bundestag in KW 24/2026 verhandelt hat" (running week: "… bisher
   verhandelt hat"); a chip per sitting linking to its dossier, the date wrapped as
   `<time datetime="2026-06-12">Fr 12.06.</time>` so the ISO date stays in the markup
   (test 417-444 asserts it); one sentence "409 Reden in 31 Tagesordnungspunkten · Stand:
   3 Sitzungen, letztes Protokoll 21/84 verteilt am 15.06.2026" (past week; when the
   newest protocol has no `verteildatum`, "letztes Protokoll 21/84 vom 12.06.2026" using
   its `datum`) or "Stand nach 1 Sitzung, die Woche läuft noch" (running week, per
   premise 2). Page actions: "Wochenvergleich", "Neuestes Protokoll". The old subtitle
   paragraph, the hero paragraph, the four fact tiles and the "Quellen" row are gone
   (raw XML/PDF/JSON links live on each dossier; the chips are the receipts).
3. **Themen der Woche** (full width). Eyebrow + h2 "Worüber am meisten gesprochen wurde"
   + one-line method note. Rows ranked by speech count across every sitting of the
   week, zero-speech and question-format TOPs excluded from the ranking; no rank
   ordinals (gate D17): the five highest counts plus every row tied with the fifth, up
   to eight; a tied group that does not fit is cut back to the last full rank and counted
   in "Weitere N". Each row:
   - type label per premise 4 ("Gesetzgebung · 1. Beratung"; "Antrag · Beratung ·
     4 Anträge gemeinsam"; "Gesetzgebung · 1. Beratung · mit 2 Anträgen");
   - lead title (wrapped in the dossier link), siblings on a "mit:" line, or for an
     equal-weight group the label as the link and all titles alike; fallback chain per
     premise 4;
   - trace, only when the row has `vorgang_ids` (336 speech-bearing items in the cache
     have no positions and get no trace line): "Fortgesetzt: Beratung in KW 42/2025 →
     Beratung diese Woche" when any of the row's `vorgang_ids` (mitberaten twins included)
     is in `returning_vorgaenge()` for this week, linking the earlier TOP (when several
     ids return, prefer the lead position's id or its twin, else the first returning id
     in DIP order); a row with no earlier occurrence shows no trace line at all (gate
     D17: the archive is not history, so no "Neu auf der Tagesordnung");
   - "19 Reden · 4,6%" with a bar relative to row 1 (the number is the honest share of
     all 409 speeches, the denominator named in the method note; the bar keeps five rows
     distinguishable);
   - "Wer sprach": exact-width Fraktion stack for that TOP (`item_stats().party_counts`,
     party colours, `title` per segment) under its own class `.who-stack` (the shared
     `.stack span { min-width:3px }` rule at build ~2697 would otherwise re-impose a
     floor) plus a text legend using the raw fraktion strings as `render_share_shift`
     does ("CDU/CSU 5 · BÜNDNIS 90/DIE GRÜNEN 4 · …") so it reads without hovering. The
     stack's total is `sum(party_counts.values())`, not `speech_count`: `item_stats`
     (render ~1072) falls back to the five-entry `xml_speakers_first` when `xml_speakers`
     is empty, so a truncated item would otherwise show 5 slices against "40 Reden". When
     `not item.get("xml_speakers")` and the item has speakers, the legend ends with
     "· nur die ersten 5 Reden erfasst";
   - KI-Zusammenfassung sentence + receipts inside a `data-feature="summaries"` block,
     rendered only when `llm_summary.text` and `source_chunks` exist for that item;
     receipts link to the dossier page anchors (`protocols/<file>.html#<anchor>` via
     `source_chunk_anchor`), not bare `#anchor`; with no summary the row has no slot;
   - "Fr 12.06. · Tagesordnungspunkt 31 · Debatte im Protokoll öffnen" linking to
     `protocols/<file>.html#top-<index>`. Rows are TOPs, not Vorgänge: a Vorgang that DIP
     matched to two TOPs of the week yields two rows (17 such cases in the cache; the
     match comes from `position_matches_top` page ranges and is not second-guessed here).
   - Under the rows: "Außerdem, nicht als Thema gerankt: Befragung der Bundesregierung ·
     116 Wortmeldungen · 28,4% (Mi 10.06., TOP 1) · … Weitere N
     Tagesordnungspunkte in den Protokollen." where N = speech-bearing TOPs of the week
     that are neither ranked nor a listed format (KW 24: 31 − 3 zero-speech − 5 − 1 =
     22). Empty state when no TOP has speeches: the section renders its header and one
     note, no rows.
4. **Wochenvergleich**: the existing four cards unchanged; a fifth card, "Namentliche
   Abstimmungen", added to the band with `data-feature="votes"`, aggregated over
   the week (`week_stats().vote_count`, plus a new `vote_top_count`). Its receipts: one
   link per sitting that has votes, "21/82 · 2 Abstimmungen", to
   `protocols/<file>.html#top-<index of that sitting's first TOP with votes>`; with no
   votes in the week, the existing "Sitzungsbelege prüfen" link to the newest dossier. The `.week-grid`
   (`repeat(2, 1fr)`) must lay out five cards, or four when the fifth is hidden
   client-side: the votes card spans both columns (`grid-column: 1 / -1`). The votes
   card renders in both band states (it needs no previous week; test 710 uses a single
   sitting and asserts `id="abstimmungen"` + `data-feature="votes"`). The "no comparison
   week" state (build ~1948) today renders only a note; it must instead keep its h2
   "Noch keine Vergleichswoche" (test 1379) and render, for the current week: the
   Wochenpuls card with metric cells built directly from `week_stats` (not from
   `comparison["metrics"]`, since `week_comparison(current, None)` returns `None`, render
   ~1226), skipping `total_chars` unless `current["chars_complete"]` exactly as
   `week_comparison` does (render ~1233), with `render_delta(None)` ("n/a") and no sparkline (`week_sparkline_points` is
   not gap-limited, render ~1341, and would leak a gap-guarded week, test 1366); the
   Redeanteil card via `render_share_shift(current, None)` (handled at ~1404); the votes
   card; and the existing note. So a single-week archive still shows the Fraktion split
   and the week totals. When the sitting counts differ, the Wochenpuls shows per-sitting
   figures (`week_comparison` normalises); the header sentence always shows raw totals.
5. **Footer** unchanged.

Anchors: `#bewegung` (linked as "Zum Lageblick") is retired with the card; `#wochenvergleich`
stays; `#abstimmungen` stays as an external deep-link target on the votes card.

Responsive and print: puls.html's own breakpoints are 980/700/460px (build ~2707-2722; the
1120/720 pair belongs to the dossier page). The radar row collapses from four columns to
one at 700px. puls.html has no `@media screen` rule today; any new rule that hides
content must be `@media screen and (...)` so print keeps it (see learnings). Dark mode
via the existing `:root[data-theme=dark]` tokens; the radar row's new classes need
explicit dark rules, not the button allowlist.

Data layer (in `scripts/render_dip_pulse_html.py`, pure functions):

- `topic_identity(item) -> {lead_title, titles, lead_type, lead_position, type_counts,
  vorgang_ids}` from `api.positions` per premise 4; `vorgang_ids` includes `mitberaten`
  twins so a row matches `returning_vorgaenge()` on any of them.
- `type_label(identity) -> str` with a small plural table
  `{"Antrag": ("Anträge", "Anträgen"), "Entschließungsantrag": ("Entschließungsanträge",
  "Entschließungsanträgen"), "Gesetzgebung": ("Gesetzentwürfe", "Gesetzentwürfen")}`;
  any other or mixed remainder uses the type-neutral "N Vorlagen gemeinsam" / "mit N
  weiteren Vorlagen" with the types listed in the element's `title`.
- `is_question_format(item) -> bool`: prefix match per premise 7.
- `week_topic_rows(week_entries, returning, limit=5) -> {rows, formats, remaining}`:
  each row carries dossier page path, sitting date + dokumentnummer, TOP index + top_id,
  speech count, share of the week (denominator = every speech in the week, formats
  included), party counts + `speakers_complete`, identity, trace, summary payload;
  excludes zero-speech and format TOPs; deterministic ties (speech count desc, then
  sitting date desc, then index asc). `formats` = the excluded, speech-bearing format
  items with count, share and href (a zero-speech Fragestunde is not listed);
  `remaining` = the "Weitere N" count.
- `format_sitting_date(datum) -> "Fr 12.06."` and `format_date(datum) -> "12.06.2026"`:
  neither module has a German date formatter today (no `strftime` use), so these are new
  helpers with a fixed weekday table (no locale dependency).
- Deleted with the Themenbewegung card: `week_headline()` (build ~1910) loses its only
  caller and goes.
- `render_week_topic_radar(radar, week) -> str` (the header owns the running-week
  wording, so the radar takes no clock).
- `render_receipts(item, stats, summary, dossier_href) -> str` extracted from
  `render_session_llm_summary` (~1844) so both callers share the link construction.
- `render_party_stack(counter, total, min_width=4.0, class_name="stack")`: the radar
  passes `min_width=0, class_name="who-stack"`; the surviving caller on the dossier page
  (render ~2079) is unchanged; the hero caller (build ~2237) is deleted.
- `week_stats()` gains `vote_top_count`.
- `render_front_page(entries, database_href, features, today=None)`.
